# iOS: передать видео через «Поделиться»

Первый эксперимент: результат сразу в Share Extension. Он не открывает
приложение-хост, не отправляет голоса и не сохраняет историю ссылок.

Выбран этот путь, потому что результат нужен сразу при просмотре видео.
Карточка показывает загрузку, оценку дизлайков, число лайков по RYD, источник,
сведения о данных, повтор при ошибке и кнопку «Готово». RU/EN, iOS/iPadOS 16+.

## Сравнение вариантов

| Вариант | Состояние | Особенности |
| --- | --- | --- |
| Карточка в «Поделиться» | Реализована | Достаточно сети, отдельное разрешение уведомлений не нужно |
| Локальное уведомление | Не реализовано | Требует разрешения; доставка зависит от системных настроек. Не является push |
| Live Activity | Не реализовано | Документированный старт из foreground приложения; нельзя считать старт из Share Extension проверенным |
| Push/APNs | Не реализовано | Потребуется сервер, регистрация токена и отдельная работа с данными/инфраструктурой |

Основание для границы Live Activity: [Apple ActivityKit](https://developer.apple.com/documentation/activitykit/displaying-live-data-with-live-activities).
Share Extension использует [стандартную точку расширения Apple](https://developer.apple.com/library/archive/documentation/General/Conceptual/ExtensibilityPG/Share.html).

## Проверки

- 14 нативных проверок парсера/ответов: watch, Shorts, live, короткая ссылка,
  текст со ссылкой, посторонний домен, несколько видео, неоднозначный query,
  неправильный ID, нули и некорректные счётчики.
- Release iOS Simulator и подписанная iOS device сборка: успешны.
- Реальный share sheet из YouTube/Safari, появление пункта в «Ещё», закрытие
  во время загрузки, отсутствие сети, поворот iPad, Dynamic Type и VoiceOver
  пока не проверены на устройстве. Сборка не доказывает эти сценарии.

Ручной проход: открыть видео → «Поделиться» → «Ещё» → YouTube Dislike;
дождаться результата, закрыть карточку и убедиться, что видео осталось открыто.
Повторить для Shorts и youtu.be, без сети и после возвращения сети.
Проверить iPhone и iPad, светлую/тёмную тему и iOS 16.

Подписанный Release установлен на физический iPhone 2026-11-02; проверка
codesign прошла. Попытка UI-проверки остановилась на `iPhone in Use` в
Mirroring: разблокированный телефон недоступен для удалённого управления.

Пользователь подтвердил открытие карточки на iPhone. После этого показатели
оформлены как две подписанные карточки «Лайки» и «Дизлайки»; у дизлайков
сохранён знак ≈. При недостатке ширины используется вертикальная компоновка.
Release device после изменения собирается. Новый вид требует визуальной проверки.

## Компактная карточка

После скриншота пользователя (слишком высокое окно) интерфейс перенесён в
собственный page sheet с detents 380 pt / large и ручкой раскрытия. Для
accessibility-размеров текста начальная высота large. Завершение по Done и
свайпу закрывает extension context. Контейнер расширения прозрачный и запрашивает
полноэкранную презентацию, чтобы не вкладывать одну системную карточку в другую.
Это изменение требует проверки реального хоста YouTube/Safari: успешная сборка
не подтверждает прозрачность контейнера и высоту удалённой презентации.
Также удалён повторяющийся подзаголовок «Two ways to check a video» (и русский).

Проверка пользователем выявила вложенные окна: системный контейнер остался
большим, собственный page sheet появился внутри него. Этот вариант отменён.
UIHostingController снова встроен как дочерний контроллер, без `present` и без
полноэкранного флага. Размер 380 pt теперь запрашивается у существующего
контейнера через preferredContentSize и его sheetPresentationController, если
он доступен. Хост может игнорировать размер удалённого расширения; компактная
высота пока не подтверждена. Release device после исправления собран успешно.
